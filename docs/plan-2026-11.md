# Plan, November 2026: work the inbox and make it routine

Supersedes `docs/handoff.md` (21 September), deleted in 2.15.2. Read AGENTS.md sections 6 and 7 first.

## Why this plan exists

The crew's design is sound and matches current guidance (hooks for hard
rules, interview before big work, review against the plan, evals before
words). What stalled is the loop: 15 field reports filed between 25
September and 7 October, plus `docs/field-reports/001`, and none worked.
The scoreboard stops at 2.15.1.

The loop stalled because it is priced per report: seed, reproduce, case,
fail, edit, suite, row, for every miss. Sixteen reports at that price is
sixteen evenings. The reports cluster into five patterns, and a pattern
is what a case measures. So the unit of work becomes the cluster.

Two environment checks are already done (8 November, real session on
the Windows laptop): background subagents keep Bash, and the guards fire
inside agents on native Windows (`PreToolUse:Bash`, `[crew hook:
guard_db]`). Nothing needs changing for either.

## The standing system

Four parts. Everything else in this file is the first run of it.

1. **Inbox.** Issues labelled `field-report`, or a numbered file in
   `docs/field-reports/` when `gh` was not available. Unchanged.
2. **Ledger.** `docs/field-reports/LEDGER.md`: one row per report.
   Columns: report, agent, cluster, kind, fix (file and one line), case,
   version, status. Status is one of `open`, `clustered`, `cased`,
   `fixed`, `declined`. A report is closed on GitHub when its row says
   `fixed` with a version, and the closing comment is the row.
3. **Two kinds of miss.** The ledger's `kind` column is `judgment` or
   `fact`.
   - *Judgment*: the agent had what it needed and chose wrong (read
     instead of ran, narrowed the dispatch, argued a risk away). Needs a
     case, because a wording change is unproven until a case fails
     without it and passes with it. One case per cluster, not per report.
   - *Fact*: the agent lacked a piece of knowledge or a hygiene rule
     (Postgres drops the default after `AddField`; do not run files you
     did not write). Goes straight into the Articles or the Captain as
     one line, paid for by a cut, with the ledger saying `no case: fact`.
     Section 7's "never an edit first" rule bends here and nowhere else.
4. **Cadence and tool.** Work the inbox when it holds three reports or
   once a month, whichever first, by cluster. A maintainer skill at the
   repo root, `.claude/skills/work-the-inbox/SKILL.md` (not shipped),
   runs it: list open reports, propose clusters and ledger rows, stop for
   a checkpoint, then for the chosen cluster: seed, add to
   `fixture_check.py`, write the case, run it and show it failing, make
   the smallest edit under budget, run the suite, fill the SCORES row,
   bump the version, close the issues with their rows. It runs on the
   laptop, where evals bill the subscription.
